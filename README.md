# Hamza Predictions — النسخة ذاتية التحديث

تطبيق توقعات مباريات بواجهة عربية، مع **وكيل تلقائي** يجمع بيانات المباريات
والترتيب من الخطة المجانية لـ API-FOOTBALL، ثم **يحسب نسبة الفوز بنفسه**
(نموذج رياضي بسيط وشفاف، وليس خدمة تنبؤ مدفوعة)، ويحدّث الموقع كل 12 ساعة.

## كيف يعمل

```
GitHub Actions (كل 12 ساعة)
        │
        ▼
agent/collect.mjs  ──▶  يجلب المباريات القادمة + ترتيب كل دوري
        │
        ▼
   يحسب نسبة الفوز بمعادلته الخاصة (فورمة + نقاط/مباراة + فارق أهداف + أفضلية الأرض)
        │
        ▼
   data/matches.json  ──▶  يُحفظ ويُدفع (commit) إلى المستودع
        │
        ▼
  Vercel / Netlify تُعيد النشر تلقائيًا فور أي تغيير في المستودع
        │
        ▼
   index.html يقرأ data/matches.json عند كل فتح للصفحة
```

النموذج **لا** يعتمد على أي خدمة تنبؤ مدفوعة — كل رقم في صفحة "التحليل
التكتيكي" مبني على بيانات فعلية (الفورمة، معدل النقاط كمضيف/ضيف، فارق
الأهداف) تم جلبها من نفس الطلب، وليس نصًا مُختلقًا.

## خطوات التشغيل

### 1) احصل على مفتاح API مجاني
اذهب إلى https://dashboard.api-football.com وأنشئ حسابًا مجانيًا (100 طلب/يوم
كافية لتغطية الدوريات المدرجة في `agent/leagues.json` مرتين يوميًا).

### 2) ارفع المشروع إلى GitHub
```
git init
git add .
git commit -m "init: Hamza Predictions"
git branch -M main
git remote add origin <رابط-مستودعك>
git push -u origin main
```

### 3) أضف المفتاح كسر (Secret)
في مستودع GitHub: **Settings → Secrets and variables → Actions → New repository secret**
- الاسم: `API_FOOTBALL_KEY`
- القيمة: المفتاح الذي حصلت عليه

### 4) فعّل الوركفلو
الوركفلو موجود في `.github/workflows/update-predictions.yml` ويعمل تلقائيًا كل
12 ساعة. يمكنك أيضًا تشغيله يدويًا فورًا من تبويب **Actions → Update Predictions
→ Run workflow** للتأكد أن كل شيء يعمل.

### 5) اربط Vercel أو Netlify بالمستودع
- **Vercel:** استورد المستودع من لوحة التحكم، بدون أي إعداد بناء (Framework: Other).
- **Netlify:** اربط المستودع، اترك أمر البناء فارغًا ومجلد النشر هو الجذر `/`.

بعد كل تحديث تلقائي من الوكيل (كل 12 ساعة)، سيدفع GitHub Actions تغييرًا جديدًا
إلى `data/matches.json`، وهذا يُشغّل نشرًا جديدًا تلقائيًا على Vercel/Netlify.

## ملاحظات مهمة

- **دقّة الجدولة:** GitHub Actions لا يضمن التشغيل في اللحظة الدقيقة كل 12 ساعة
  (قد يتأخر بضع دقائق حسب ازدحام الخدمة) — هذا طبيعي ومتوقع من أي cron مجاني.
- **حصة الطلبات المجانية:** كل تشغيل يستهلك طلبًا واحدًا لكل دوري لتحديد هويته
  (مرة كل 25 يومًا فقط بفضل التخزين المؤقت في `agent/cache.json`) + طلبين لكل
  دوري (مباريات + ترتيب) في كل تشغيل. بالإعدادات الحالية (7 دوريات × مرتين
  يوميًا) الاستهلاك حوالي 28 طلبًا يوميًا — ضمن الخطة المجانية بأمان.
- **الدوريات المدرجة:** عدّل `agent/leagues.json` لإضافة أو حذف دوريات. استخدم
  اسم الدولة والدوري كما تُعرف في API-FOOTBALL.
- **معاينة Claude:** النسخة المعروضة داخل هذه المحادثة تستخدم بيانات تجريبية
  ثابتة لأن معاينة Claude لا تصل لملفات خارجية؛ التحديث التلقائي الفعلي يعمل
  فقط بعد النشر على Vercel/Netlify مع تفعيل GitHub Actions كما هو موضح أعلاه.
